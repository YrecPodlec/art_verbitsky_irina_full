# Импорт проектов из существующих папок Blob

## Что уже загружено

В `portfolio.projects` находятся 19 проектов и 192 ссылки на изображения.
Старый Майами не изменён; добавлены 18 новых опубликованных проектов.
Все жилые, кроме `office_miami` → `commercial / office`.
`2_old_cuple` → квартира для пары (`residential / apartment`).

По договорённости неочевидные категории выбраны предварительно: «Кошки»,
детская, ванная Майами, «Зима / Лето» — квартиры; баня — дом.
Площадь и год не придуманы. Неизвестные страна/город остаются пустыми в БД,
а в переводах отображается «Локация уточняется». Все текущие изображения —
визуализации; чертежи и фотографии реализации не подменялись рендерами.

Два кадра встречаются в двух папках: `8_kidsroom/9.webp` = `miami_bath/7.webp`
и `8_kidsroom/10.webp` = `miami_bath/8.webp`. Их оставили в обоих проектах.
Исходники в Blob не удалялись, не сжимались и не перезаписывались.

## Где править

- **Тексты:** `messages/ru.json` и `messages/en.json` → `projects.<contentKey>`.
  Здесь название, описание, история, страна/город, `media.<contentKey>.alt/caption`.
  Новые описания базовые, истории явно временные — можно заменить своими.
- **Свойства уже созданного проекта:** MongoDB Compass → `portfolio.projects`.
  Здесь `type`, `category`, `featured`, площадь, год, обложка и `media`.
  На сайте данные по-прежнему читаются из MongoDB, а не из импортного JSON.
- **Настройки следующего импорта:** [project-import.catalog.json](project-import.catalog.json).
  Это соответствие `folder → slug/contentKey/type/category`, не второй источник данных сайта.
  Его изменение не обновит существующий документ: импорт намеренно пропускает такие записи.

Например, ключ `apartmentForTwo` связывает квартиру для двоих с
`messages.projects.apartmentForTwo`; `miamiOffice` — офис в Майами.
Для новых проектов `featured: false`: подборка на странице интерьера не менялась.

## Как повторить проверку / добавить отсутствующие папки

Секреты остаются в `.env`: `DATABASE_URL` (база `/portfolio`) и
`BLOB_READ_WRITE_TOKEN`. Токен нужен только для получения списка файлов,
в браузер и публичные запросы изображений он не передаётся.

```powershell
npm run db:inspect-images
npm run db:import-projects
# Только после проверки списка add/skip:
npm run db:import-projects -- --apply
```

Первый шаг только читает Blob, скачивает/декодирует каждое изображение и получает
настоящие размеры/вес. Отчёт и контактные листы пишутся в `.next/blob-inspection/`
(игнорируются Git, могут исчезнуть при сборке). Отчёт действителен 24 часа.
Перед добавлением новых папок проверь контактные листы и заполни переводы
в обоих JSON. Сборщик создаёт стабильные ключи из имён файлов; выбранная обложка
получает ключ `cover`. Порядок естественный: 1, 2, ... 10.

Без `--apply` идёт только чтение: проверяются изображения, переводы, категории,
коллизии `slug/contentKey`, уникальные индексы и существующее правило коллекции.
При `--apply` добавляются **только отсутствующие** проекты одной транзакцией.
Повторный запуск не создаёт дубликаты и не перезаписывает ручные правки.
Импорт также устанавливает нативное правило MongoDB `type/category` в режиме
`strict/error`. Неизвестный существующий валидатор он не затирает — остановится.

`prisma generate` не записывает данные и не устанавливает правило MongoDB.
На Windows при ошибке блокировки `query_engine-windows.dll.node` останови
свой `npm run dev`, выполни `npm run db:generate` и запусти dev снова.

## Проверки без изменения данных

```powershell
npm run test:project-import
npm run test:projects
npm run test:project-api
npm run test:portfolio
npm run check:messages
# При запущенном npm run dev:
npm run test:portfolio:http -- --all-projects
```

Последняя команда проверяет все страницы каталога, каждый кейс на ru/en,
фильтр офиса и загрузку обложек через оптимизатор Next. Только GET, без записей.
Водяные знаки, дополнительные файлы и деплой импорт не создаёт.
