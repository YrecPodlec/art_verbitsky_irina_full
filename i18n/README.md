| Файл | Ответственность |

| [routing.ts](routing.ts) | Список локалей, язык по умолчанию и наличие префикса |
| [request.ts](request.ts) | Выбор допустимого языка и загрузка его JSON |

Сейчас доступны `en` и `ru`, по умолчанию — `ru`, префикс — `always`.
Поэтому языковые страницы имеют вид `/ru/interior` и `/en/interior`.

## Ссылки в компонентах

```tsx
import {Link} from '@/i18n/navigation';

<Link href="/gallery">{label}</Link>
<Link href="/interior" locale="en">{englishLabel}</Link>
```

В обычном внутреннем href не нужно вручную добавлять текущий язык.
Для якоря в том же документе используется `#contacts`; для определённой страницы —
`/interior#contacts`.

Переключатель языка использует pathname и prop `locale`.
Текущая реализация не переносит query/hash отдельно:
[LanguageSwitcher](../app/[locale]/features/languageSwitcher/README.md).

## Добавить язык

1. Скопировать `messages/en.json` в `messages/<код>.json`.
2. Перевести значения, сохранив ключи, параметры, теги и массивы.
3. Добавить код в `routing.locales`.
4. При необходимости добавить флаг в `shared/assets/flags` и сопоставление в переключателе.
   Без него будет отображаться глобус.
5. Проверить новый маршрут, меню, длинные подписи и сборку.
6. Для письма справа налево отдельно добавить направление интерфейса и проверить раскладку.

`request.ts` динамически загружает JSON по коду локали.
`layout.tsx` проверяет код через `hasLocale`; его `generateStaticParams`
берёт тот же список локалей.

## Серверные и клиентские тексты

На сервере можно получать строки через `getTranslations` и `getMessages`.
Клиентскому `useTranslations` нужен доступный ему словарь.
Сейчас общий провайдер в layout передаёт только `siteHeader`;
форма и тарифы получают готовые данные через props.

Добавляя клиентский компонент, либо передай ему готовые переводы,
либо настрой передачу нужного namespace. Не рассчитывай, что все JSON автоматически
оказались в браузере.

Структура и поиск текста: [messages](../messages/README.md).
