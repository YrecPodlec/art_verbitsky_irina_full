# ProjectInquiry — выбор услуги и обращение по проекту

Эта feature связывает карточки тарифов, ссылки консультаций и контактную форму.
Начни здесь, если непонятно, как выбранная услуга оказывается в поле формы.

## Карта файлов

| Файл | Задача |
| --- | --- |
| [model/InquiryProvider.tsx](model/InquiryProvider.tsx) | Общие `service` и `preview`; контекст `useInquiry` |
| [ui/ServicePackageChoice.tsx](ui/ServicePackageChoice.tsx) | Выбранный вариант одной карточки тарифа |
| [ui/ServiceChoiceLink.tsx](ui/ServiceChoiceLink.tsx) | Выбрать услугу и перейти к `#contacts` |
| [ui/ContactForm.tsx](ui/ContactForm.tsx) | Поля, кнопки и экран демо-подтверждения |
| [model/useContactForm.ts](model/useContactForm.ts) | Готовность формы, обработка submit и перенос фокуса |
| [index.ts](index.ts) | Экспорты для страницы и widgets |

Сетка полей — в `ContactForm.module.scss`; вид переключателей —
в `ServicePackageChoice.module.scss`. Вид всей карточки тарифа задаётся в
[entities/service](../../entities/service/README.md), общие поля —
в [shared/UI/formField](../../shared/UI/formField/README.md).

## Как проходит выбор

1. Серверный `InteriorServices` получает локализованные пакеты через `getServices`.
2. `ServicePackageChoice` хранит номер выбранного варианта в `selected`.
   Он передаёт вариант в `ServiceCard`, а его ID — в `ServiceChoiceLink`.
3. Нажатие «Выбрать» вызывает `selectService(id)` и переход к якорю `#contacts`.
4. `InquiryProvider` записывает ID в `service` и закрывает прежнее подтверждение.
5. `ContactForm` читает тот же контекст. Её select использует `value={service}`.

Простое переключение варианта внутри карточки ещё не выбирает услугу формы:
она меняется после нажатия ссылки или ручного выбора в select.
ID вроде `basicDrawings` не переводятся; подписи переводятся через `services.options`.

## Где хранится состояние

`InquiryProvider` подключён вокруг содержимого страницы `interior`.
Он хранит:

- `service` — ID услуги, сначала `undecided`.
- `preview` — показывать ли демо-подтверждение, сначала `false`.

Компоненты, вызывающие `useInquiry`, должны находиться внутри этого провайдера.
Серверные блоки переданы ему через `children`; их код не импортируется провайдером.
При использовании формы на новой странице подключи там ту же обёртку.

## Как работает форма

Обязательны имя, email и страна/город. Площадь необязательна, но если задана —
от 1 до 100000. Формат email проверяется браузером. Ограничения длины стоят на полях.

`useContactForm.submit` отменяет стандартную отправку через `preventDefault`
и после проверки показывает подтверждение. Запросов к API, сохранения на сервере
или в `localStorage` сейчас нет.

Форма скрывается через `hidden`, но остаётся смонтированной. Поэтому введённое
сохраняется при возврате в пределах текущего экземпляра формы.
После перезагрузки оно не восстанавливается.

`nameRef` и `previewRef` дают доступ к элементам для `focus()`.
`wasPreview` помнит, был ли показан экран подтверждения, чтобы не фокусировать имя
при первом открытии страницы. Эти refs не определяют выбранную услугу.

`ready` через `useSyncExternalStore` сначала возвращает серверное значение `false`,
затем клиентское `true`. До подключения обработчиков fieldset отключён,
чтобы браузер не отправил поля обычным HTML-submit.
`useId` связывает форму с примечанием через `aria-describedby`.

## Тексты и подключение

Тексты полей и подтверждения находятся в `messages.contactForm`,
названия услуг — в `messages.services`. Серверный `InteriorContact` передаёт
только эти нужные данные через `copy` и `services`.

Тип `ContactFormMessages` выводится из структуры английского словаря через
`import type`: английские значения из-за этого импорта не подменяют русские.

## Что менять

- Новое поле: JSX в `ContactForm`, переводы и правила проверки; при будущей отправке — серверную схему.
- Новый тариф: модель и переводы [entities/service](../../entities/service/README.md).
- Поведение выбора: `ServiceChoiceLink` и `InquiryProvider`.
- Поведение после submit: `useContactForm` и экран preview в `ContactForm`.
- Настоящая отправка: добавить серверный обработчик, серверную проверку данных,
  состояния ожидания/ошибки/успеха; успешный экран показывать только после подтверждённой отправки.

После изменения проверь выбор каждого варианта и консультации, ручной select,
неверный email, пустую форму, submit, возврат с сохранённым вводом
и новый выбор тарифа после preview. Полный список — в
[README страницы](<../../(pages)/interior/README.md#как-проверять>).
