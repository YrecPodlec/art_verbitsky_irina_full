# Каталог и страницы проектов

Адреса: `/ru/gallery`, `/en/gallery`; кейс — `/ru/gallery/miami-house`.
В списке одна карточка на один документ MongoDB. Десять изображений Майами —
это десять элементов его `media`, а не десять проектов.

## Где менять

| Что | Файл или папка |
| --- | --- |
| Сборка каталога | `page.tsx` |
| Сборка кейса, metadata и хлебные крошки | `[slug]/page.tsx` |
| Общая оболочка и футер | `layout.tsx` |
| Сетка карточек, внешние отступы пагинации и фон | `portfolio.module.scss` |
| Номера страниц и стрелки | `shared/UI/pagination` |
| Первый экран | `widgets/portfolioHero` |
| Фильтры и поиск | `features/filterProjects` |
| Разделы подробного кейса | `widgets/projectCase` |
| Изображения и увеличенный просмотр | `features/viewProjectMedia` |
| Запросы к MongoDB | `entities/project/api/getProjectCatalog.ts` |
| Преобразование записей в локализованные данные UI | `entities/project/model/getProjects.ts` |
| Карточка (общая с Interior) | `entities/project/ui/ProjectCard.tsx` |

Все пути слоёв выше находятся внутри `app/[locale]`. Небольшие общие элементы:
`shared/UI/iconButton`, `portfolioState`, `refreshButton`. Для кнопок переиспользуется
`shared/UI/actionLink`, для навигации — существующий `Breadcrumbs`.

## Данные и переводы

Next читает MongoDB на сервере. Серверным компонентам не нужен HTTP-запрос
к собственному `/api/projects`: API остаётся доступным для внешнего/клиентского чтения.
Публикация, фильтры, подсчёт и пагинация по 6 записей выполняются в БД.
Лимит — `entities/project/model/catalogQuery.ts` → `CATALOG_PAGE_SIZE`.
Номеров столько же, сколько страниц; текущая выделена. Обе горизонтальные стрелки
видны всегда, на краях отключены. Фильтры и поиск сохраняются при переходе.
Даже для одной страницы видны номер 1 и две неактивные стрелки.

Порядок явный: сначала закреплённый Майами, затем остальные по `createdAt` убыванию
и `id` возрастанию. Приоритет — `entities/project/model/projectOrder.ts`;
общий запрос каталога/API/подборки — `api/findOrderedProjects.ts`.
Фильтры применяются и к Майами: офисный фильтр не подтягивает его принудительно.
Смещение следующих страниц учитывает закреплённую запись, без повторов и пропусков.
Порядок документов в Compass ничего не меняет; даты создания не подменяем.
`featured` по-прежнему отвечает только за подборку Interior, не за порядок.

Первый экран использует серверный `entities/project/ui/ProjectCoverImage`:
одна статичная обложка Майами из MongoDB, без слайдов и переключателей.
Поиск проверяет локализованные name/country/city/summary/description в messages
и передаёт в MongoDB соответствующие `contentKey`; slug и citySlug ищутся точно.
В клиент не отправляется вся коллекция проектов.

В БД: `contentKey`, характеристики, ссылки и метаданные файлов. В словарях:

- `gallery` — каталог, фильтры, ошибки и пагинация;
- `projectCase` — названия разделов, базовые тексты-заглушки, просмотрщик;
- `portfolioInvitation` — общая нижняя секция приглашения;
- `projects.miami` — название, описание, история и переводы изображений Майами.

Чтобы заменить заглушку конкретного раздела **одного** проекта, добавь одинаковый
ключ в обе локали, например `projects.miami.details.layout` или
`projects.miami.details.concept`. Значение — обычная строка. Без такого ключа
используется `projectCase.sections.layout.body` (или соответствующий раздел).
Вводный раздел читает `projects.miami.description` и `projects.miami.story`.

`media[].category` распределяет файлы: `visualization` → визуализации,
`concept` → концепция, `drawing` → рабочая документация, `photo` → результат.
Описание картинки — `projects.miami.media.<contentKey>.alt`, подпись — `.caption`.
Без чертежей/фото показывается явно подписанное место под материалы, не фиктивный план.
Исходные данные и объяснение планировки пока представлены текстовыми заготовками.

Избранное остаётся заготовкой до аккаунта; кнопка намеренно disabled.
Не добавляем поддельные записи ради заполнения сетки. Новые проекты публикуются
через текущую форму после подготовки переводов. Изменения переводов требуют
пересборки приложения; чтение новых опубликованных записей — нет.

## Проверки

```powershell
npm run test:portfolio
npm run test:projects
npm run test:project-api
npm run check:messages
```

При работающем `npm run dev`:

```powershell
npm run test:portfolio:http
```

HTTP-тест делает только GET: ru/en, карточка, кейс, фильтр, поиск, пустая выдача,
несуществующий slug и **все изображения первого проекта через оптимизатор Next**.
Можно задать `PORTFOLIO_BASE_URL` для другого локального порта. На внешних доменах
этот скрипт запускаться отказывается. Записи в MongoDB тесты не добавляют.

Вручную в браузере: 1440/768/390 px; открыть картинку, переключить стрелками
и миниатюрами, закрыть Escape, проверить возврат фокуса и отсутствие фоновой прокрутки;
проверить фильтры, Enter в поиске, Back/Forward, переходы по боковым якорям и смену языка.
Для реальной пагинации нужны более 6 опубликованных проектов; без них проверяется
нормализация URL, но искусственные проекты в БД не создаются.

Нативный `<dialog>` удерживает фокус. Сервер возвращает 404 для отсутствующего
кейса до начала стриминга; при уже начавшемся стриминге Next может вернуть HTTP 200
с состоянием not-found и `noindex` — это учитывает HTTP-тест.
