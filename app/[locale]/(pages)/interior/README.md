# Страница дизайна интерьера

`page.tsx` собирает только `/[locale]/interior`. Источник дизайна — `maket/index.html`,
`maket/content.js`, `maket/styles.css`, `maket/site.css` и интерактивность из `maket/app.js`.
Другие маршруты не переносятся в рамках этой страницы.

## Структура

Все пути ниже отсчитываются от `app/[locale]`.

| Папка | Назначение |
| --- | --- |
| `widgets/interiorHero` | Первый экран и хлебные крошки |
| `widgets/featuredProjects` | Второй блок с тремя проектами |
| `widgets/interiorServices` | Пакеты, особый подход и консультации |
| `widgets/workProcess` | Этапы работы и схема планировки |
| `widgets/designerAbout` | Портрет, текст об Ирине и принципы |
| `widgets/showroomTeaser` | Превью шоурума со ссылкой на отдельную страницу |
| `widgets/interiorContact` | Контактный блок и подключение формы |
| `widgets/interiorFooter` | Подвал, подключённый только к interior |
| `entities/project` | Данные проектов и переиспользуемая карточка |
| `entities/service` | Пакеты услуг и карточка без собственного состояния |
| `features/projectInquiry` | Выбор пакета, перенос услуги в форму и демо-подтверждение |
| `features/favoriteProject` | Заготовка будущего избранного |
| `features/sectionNavigation` | Якорная навигация, прогресс чтения и возврат наверх |
| `shared/UI/section` | Общие отступы секций, верхняя строка, заголовки и примечания |
| `shared/UI/actionLink` | Общие ссылка и кнопка со стрелкой, без копирования стилей |
| `shared/UI/accordion` | Раскрывающийся пункт на нативном `details` |
| `shared/UI/formField` | Общая подпись и оформление полей формы |
| `shared/UI/floorPlan` | Векторная схема из макета |

Страница импортирует виджеты и features; виджеты соединяют features, entities и shared.
Entity не импортирует feature: действия передаются слотами (`favoriteAction`, `controls`, `action`).
`entities/service/server.ts` — отдельный вход для серверного адаптера данных.

## Сервер, клиент и переводы

Виджеты получают переводы на сервере. Все тексты находятся в корневых `messages/ru.json`
и `messages/en.json`; клиентские компоненты получают только необходимые готовые строки.
Список услуг использует стабильные ID: при переводе языка код формы менять не нужно.

`InquiryProvider` хранит выбранную услугу и состояние подтверждения. Он принимает серверные
виджеты через `children`, поэтому вся страница не превращается в клиентский компонент.
`ServicePackageChoice` хранит выбранный вариант конкретного пакета, а `useContactForm`
отделяет поведение формы от её разметки. `useReadingProgress` отделяет измерения страницы
от боковой навигации. Дополнительные `useMemo`/`useCallback` без необходимости не используются.

Страница статически генерируется для обеих локалей. Картинки ниже первого экрана загружаются
лениво через `next/image`; исходные изображения уже находятся в `public/interior`.
Все стили компонентов — соседние SCSS-модули. Палитра и длительности анимаций — `globals.css`.
Основные размеры используют шаг `.25rem`; декоративные тонкие линии сохранены из макета.
Анимация раскрытия `details` — прогрессивное улучшение CSS: без поддержки новых свойств
остаются доступными раскрытие с клавиатуры и весь текст. Учитывается `prefers-reduced-motion`.

Подход к серверным children и передаче переводов соответствует документации
[Next.js](https://nextjs.org/docs/app/getting-started/server-and-client-components)
и [next-intl](https://next-intl.dev/docs/environments/server-client-components).

## Что пока демонстрационное

Сердечки отключены до появления аккаунта и API избранного. У карточки проекта есть
необязательный `href`: его передадим после создания настоящего маршрута кейса.
Форма проверяет обязательные поля и email, показывает демо-подтверждение, но ничего не
отправляет и не сохраняет в хранилище. До загрузки JavaScript её поля отключены.
Повторный выбор услуги открывает форму снова; возврат из подтверждения сохраняет введённое
в текущей вкладке. После перезагрузки данные не восстанавливаются.
Цены, контакты и юридические сведения требуют согласования. Ссылка на UI-kit из прототипа
не добавляется в публичный футер; профиль использует уже существующую заглушку.

## Как проверять

1. `npm run lint` — проверка правил проекта; `npm run build` — типы и production-сборка.
2. Открыть `/ru/interior` и `/en/interior`; сравнить с макетом при ширине 1440, 1024,
   800, 520 и 375 px. Проверить отсутствие горизонтальной прокрутки и обрезанного текста.
3. Во втором блоке: три карточки, изображения, неактивные сердечки, переходы в галерею,
   шоурум и к услугам. На телефоне карточки идут в одну колонку.
4. В каждом тарифе переключить оба варианта. Нажать «Выбрать»: в форме должна оказаться
   именно выбранная услуга. Проверить также обе консультации и особый подход.
5. Проверить пустую форму и неверный email; затем заполнить тестовыми данными.
   Должно появиться явное демо-подтверждение без сетевой отправки и без данных в URL.
   Вернуться в форму, проверить сохранение ввода; выбрать другой тариф после подтверждения.
6. Раскрыть этапы мышью и клавиатурой, проверить боковые якоря и кнопку наверх.
   Проверить Tab, видимый фокус, масштаб 200% и уменьшение анимации в настройках системы.

Проверки сборки и серверного HTML не заменяют визуальную проверку и сценарии в браузере.
