# WorkProcess — этапы работы

Серверный раздел с якорем `process`.
[ui/WorkProcess.tsx](ui/WorkProcess.tsx) собирает вводную часть, планировку и пять этапов.

Массив `steps` задаёт порядок: `sketch`, `visual`, `documents`,
`supervision`, `procurement`. Текст — в `messages.workProcess.steps.<id>`:
`name`, `do`, `get`, `example`.

Чтобы добавить этап, обнови массив и объект перевода в каждой локали.
Первый пункт получает `defaultOpen`; номера выводятся из порядка массива.

Раздел использует [AccordionItem](../../shared/UI/accordion/README.md).
Его общий вид и механизм раскрытия меняются в shared, а оформление текста,
схемы примера и композиции раздела — в
[ui/WorkProcess.module.scss](ui/WorkProcess.module.scss).

Вместо декоративного `FloorPlan` используется картинка `public/plan.png`.
Она импортируется через Next Image с **unoptimized**: Next не уменьшает и не
перекодирует PNG. `quality`/`sizes` не задаются: отдаётся оригинальный файл,
а адаптивный размер задаёт CSS без обрезки. Загрузка lazy.
Картинка не является ссылкой: открытия по клику и подписи под ней нет.
Alt — `workProcess.planAlt` в ru/en. Максимальная ширина — 28rem (448px),
на телефонах изображение адаптируется к ширине контейнера.
Статический импорт меняет хеш URL после замены файла, не используя старый кеш оптимизатора.
Расположение — `.plan`, размер картинки — `.planImage` в соседнем SCSS-модуле.
Прежняя PDF-версия отменена; исходные PDF пользователя не изменялись.

Проверка реальных байтов: при работающем Next выполни
`node scripts/test-work-plan-http.mjs`. Тест сравнивает SHA-256 картинки с исходником
и проверяет, что src не идёт через `/_next/image`. Он делает только локальные GET.

Все тексты готовятся на сервере; браузер управляет раскрытием `details`.
Проверяй порядок этапов, первый открытый пункт, клавиатуру, длинные тексты
и изменение высоты страницы при раскрытии.
