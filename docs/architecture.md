# Архитектура и порядок работы

## Источник дизайна

Папка `maket/` — утверждённая отправная точка для визуального оформления: композиции, отступов, цветов, шрифтов и адаптивных состояний. При переносе HTML разметка превращается в React-компоненты; прямые операции с DOM из `maket/app.js` не копируются. Изображения и шрифты, необходимые работающему сайту, лежат в `public/interior/`.

## Слои FSD

```text
app/            URL, layout, metadata
src/_pages/     сборка целой страницы из блоков
src/widgets/    крупные блоки страницы
src/features/   действия пользователя и локальное состояние
src/entities/   предметные данные и их отображение
src/shared/     общие элементы, когда они действительно понадобятся нескольким частям
```

Зависимости направлены вниз: маршрут импортирует FSD-страницу; страница собирает widgets; widget может импортировать feature и entity; feature может импортировать entity. Внутри каждого слоя файлы лежат рядом со своей задачей, а публичный `index.ts` скрывает внутренние пути. Пока компонент нужен только в одном widget, не переносим его преждевременно в `shared`.

Каждый новый компонент содержит короткий комментарий о его ответственности. Важные решения и временные ограничения тоже комментируем; очевидные JSX-строки построчно не объясняем.

## Локализация

Все тексты интерфейса, карточек, формы, альтернативные подписи изображений и SEO-метаданные лежат в `messages/<locale>.json`. Компоненты используют `useTranslations`, а метаданные — `getTranslations` из `next-intl`. В моделях остаются только устойчивые идентификаторы, порядок и нетекстовые данные; двуязычные объекты в TypeScript не нужны. Языки перечислены в `i18n/routing.ts`, а `i18n/request.ts` загружает соответствующий JSON.

Чтобы добавить язык, копируем `messages/en.json`, переводим значения без изменения ключей, добавляем код языка в `routing.locales` и запускаем `npm run check:messages`. Проверка сравнивает структуру словарей. Качество перевода и переносы строк в заголовках проверяем визуально.

## Текущий статус

- `/ru/interior` и `/en/interior`: первый перенос главной страницы из `maket/index.html` — шапка, hero, проекты, услуги, этапы, подход, тизер шоурума, контакты и футер.
- Карточки проектов и пакеты услуг демонстрационные, как в исходном макете. Страницы отдельных кейсов, галерея, статьи, профиль и интерактивный шоурум будут отдельными этапами.
- Контактная форма пока показывает только предпросмотр подтверждения. Перед настоящей отправкой потребуются способ доставки заявки, проверка данных на сервере и согласованные юридические тексты.

## Документация и проверки

После каждого законченного раздела обновляем статус выше и README, если меняется запуск или структура. Проверяем словари (`npm run check:messages`), TypeScript, ESLint и production-сборку. Для вёрстки дополнительно сверяем страницу с макетом на широком экране и телефоне, включая меню, клавиатурную навигацию и оба языка.

Автоматические тесты добавляем для поведения, которое можно сломать: выбор варианта услуги, валидация и отправка будущей настоящей формы, фильтры галереи, сохранение избранного. Тесты должны проверять результат для пользователя, а не повторять внутренний код компонента. Для статической разметки достаточно сборки, линтера и визуальной проверки.
